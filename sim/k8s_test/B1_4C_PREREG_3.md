## 1. 一个问题

> **Q：两边首次分歧的那一步，两台机器是不是本来就"几乎不在乎"该选哪个词？**
> （口径：用 **processed 分**衡量"在乎程度"——这才是选词实际用的分。）

## 2. 分数来源（本方案的关键新增条，冻结）

- 两条臂的服务**必须**以 `--logprobs-mode processed_logprobs` 启动；判据一律用 processed 分。
- **raw 分不参与判定**（它会系统性说谎）；若采集顺手可另存作对照，不强制。
- 上报值是 **log 空间**（负数）：**一律 `exp()` 换算成概率后再算**（与既有报告口径一致）。
- **每臂开测前先过 C1 冒烟**：同一服务上跑 **q01_rep6 / q02_rep10 / q03_rep14** 三条（不进统计），
  检查"吐词 == processed 第一名"全过才开测；不过**不采数**（说明该环境的 processed 口径
  不成立，回校准，不硬测）。

## 3. 提示词（冻结）

`b1_client.py gen-prompts --preset v2` 的 5 条（`q01_rep6 … q05_rep22`，逐字符由脚本确定性生成，
sha256 留档并与 `B1_4C_PREREG_2.md` §2 规格核对）。**该题组从未参与任何采数**
（PREREG_2 暂停时一次请求都没发），符合裁定 6"使用未参与本轮的提示词"。

## 4. 采数协议（冻结）

- **两臂**（与 B1 相同的部署形态）：对照臂＝单机完整服务；拆分臂＝前处理 → KV 传输 → 生成 + 代理。
  **唯一新增**：启动参数加 `--logprobs-mode processed_logprobs`。
- 其余与 B1 **逐条相同**：同模型 revision（`989aa798…`，两端目录哈希核对）、bf16、
  `--enforce-eager --no-enable-prefix-caching --max-model-len 8192 --gpu-memory-utilization 0.85`、
  请求 `temperature=0 / seed=0 / max_tokens=64 / return_token_ids=true / logprobs=20`、**串行**。
- 前缀缓存**关闭**，以 `/metrics` 的 `enable_prefix_caching="False"` 原文为证（不看命令行）。
- 预热：每臂 3 遍完整 5 条（不进统计）；正式：每臂 3 遍（r1..r3）；臂顺序固定
  **先对照、后拆分**。
- 逐请求原样落盘（token_ids + processed 分 + 原始响应），失败不重跑顶替；
  `record.csv` 记 UTC 起止 / 退出码；跑完按 PID 精确停服务。

## 5. 指标（冻结；**全部只作描述，不设通过线**）

设首次分歧在下标 **i**：`a` = 对照臂选的词，`b` = 拆分臂选的词；
`pa/pb` = 对照臂 processed 分给 `a`/`b` 的概率，`qa/qb` = 拆分臂给 `a`/`b` 的概率。

- **E4（作者点名的主输出）**：逐条列出 **(pa, pb, qa, qb) 绝对值表**——
  "两边在首次分歧处对**实际竞争的那两个词**分别给了多大概率"就是这张表，**不压缩成单一指标**。
- **E1（复用 PREREG_2 定义）**：`r_base = pb/pa`，`r_disagg = qa/qb`，`m = min(r_base, r_disagg)`；
  分档 A（m ≥ 0.90，两边都近乎并列）/ B（0.50 ≤ m < 0.90）/ C（m < 0.50，各有明确偏好），
  **只作描述，不是判定**。
- **E2（复用 PREREG_2 定义）**：噪声地板 Δ＝两臂**选同一个词**的步上、top-20 交集内概率最大
  绝对差（报中位与 p90）；决策余量 M＝分歧步上 |pa−pb|、|qa−qb|；报 **M/Δ**
  （≤1 与数值噪声相容；≫1 不相容）。**只用于解释。**
- **E3（测量自检）**：同臂 r2 vs r3 逐 token 逐位相同；不过先修测量、**不解读** E1/E2/E4。
- **逐位相同的题**照实记"无比可算"（不跳过、不补猜）。
- 报告要求：完整分布（min/med/max）+ 分档计数 + 逐条明细 + **两臂各自三遍的原始数据**都留档。
