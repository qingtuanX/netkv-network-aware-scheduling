## 1. 三个问题（替代"整段文字是否逐字相同"）

| 层 | 问题 | 手段 |
|---|---|---|
| Q1 配置同一性 | 两条臂的模型、精度、生成参数、vLLM 版本是否逐项相同、且**真的生效**？ | §2 参数写死 + §2.1 留证 |
| Q2 状态同一性 | **相同前缀**下，两臂对下一词的评分分布是否一致？ | §3 固定前缀测试（teacher forcing） |
| Q3 分歧归因 | 若不一致，是"并列翻转"（数值路径敏感）还是"真不一致"（KV/精度问题）？ | §4 判定 + §6 干预臂 |

**为什么固定前缀测试是核心**：自由生成时一个词的微小差异会越走越远（前缀从此不同），
整段文字比对把"一步数值抖动"放大成"整段不同"。固定前缀 = 每一步两边看到**完全相同的输入**，
直接检验"KV 传过去后，相同前缀下下一步判断是否一致"。

## 3. 固定前缀测试协议（冻结）

**诊断题（冻结）**：v2 题组 5 条——`b1_client.py gen-prompts --preset v2`
（`q01_rep6 … q05_rep22`，逐字符规格见 `B1_4C_PREREG_2.md` §2 / `b1_client.py` 注释）。

> **题组定位（冻结）**：v2 题组属于**针对已知分歧的重复验证集**，其中 **q04 是已知分歧的
> 阳性对照**。本轮结果只用于判断**该类分歧的机制**，不代表所有提示词上的普遍等价性。
> （这 5 条已经看过自由生成的结果，不能再当"完全独立、代表所有输入"的测试集。）

**步骤**：

1. **参考序列**：对照臂对每条诊断题自由生成（`max_tokens=64`），取 token 序列 `t1..tL`。
   整段文字比对（旧 4c 口径）作为**附加观察**照常记录，不进判定。
2. **逐步回放**：对每个 k = 1..L，把 **prompt 的 token ids + t1..tk** 同时喂给两臂，
   `max_tokens=1, logprobs=20`，取两臂的下一词评分分布（processed，exp 后普通概率）。
   - 前缀以 **token id 原样拼接**（不用文本重编码，避免分词差异）；若代理不透传 token-id
     列表，退化为文本回拼，但必须**逐 token 对账**（回拼后重新 tokenize 与原 ids 不一致的步
     **弃用并报告**）。
   - 全回放（5 题 × ≤64 步 × 2 臂 ≈ 640 请求，串行），**不做降采样**；时间不够砍干预臂
     （§7 优先级），不砍回放。
3. **每步记录**：两臂 top-20（token id + processed 概率）、两臂 top1 选择、`prompt_tokens`、
   KV 指标增量、原始响应。
4. **E3 式自检（每臂每题开测前）**：同一前缀同臂连续 2 次回放必须**逐位相同**；否则停下修
   测量，不解读任何判定。

## 4. 判定口径（Δ_gap 版，按作者审核意见修订后冻结）

全部用普通概率（log 空间先 `exp()`）。记号：

- **同词步**：两臂 top1 选了同一个词的回放步；**分歧步**：两臂 top1 不同的步。
- 每步取两臂 **top-20 候选的交集** `I`（两臂都出现的 token）。

**Δ_gap（两条路径对"相对差距"的扰动上界）——在同词步上估计**：

对每个同词步、对交集 `I` 中每一对不同候选 `x, y`，计算

```
g(x, y) = | (p_base(x) − p_base(y)) − (p_split(x) − p_split(y)) |
```

即"两条计算路径最多把 **x 相对于 y 的领先程度** 改变了多少"。把所有同词步的所有候选对的
g 值汇在一起：

- **Δ_gap_p95** = 95% 参考上界（p95）；
- **Δ_gap_max** = 最大值；
- 同时报中位数。**95% 参考上界不叫"最大扰动"**，措辞按此为准。

**样本量条件（硬性）**：可用于估计 Δ_gap 的同词步（交集内至少 1 个候选对）
**少于 30 步** ⇒ Δ_gap **不可估计** ⇒ **4c 不判通过、B2 不放行**，如实记"数据不足"。

**分歧步的判定量**：设 `a` = 对照臂选出的 token、`b` = 拆分臂选出的 token（即实际翻转的
那一对）。要求 **a、b 都出现在两边的 top-20 记录里**；然后

```
G = min( |p_base(a) − p_base(b)| , |p_split(a) − p_split(b)| )
```

即"两个实际竞争词之间的差距"（取两臂里较弱的那个），与 **Δ_gap_p95** 比较：
差距比路径可能造成的相对变化还小 ⇒ 翻词可由数值解释；比它大还翻 ⇒ 解释不通。

| 类型 | 条件 | 结论 |
|---|---|---|
| **A 明显一致** | 两臂 top1 同词 | 通过 |
| **B 并列翻转** | top1 不同；a、b 均在两臂 top-20；**G < Δ_gap_p95** | 记"执行路径敏感（tie-flip）"，**不算 KV 错误** |
| **C 明显不一致** | top1 不同；a、b 均在两臂 top-20；**G ≥ Δ_gap_p95**；或任一步出现本地重算 / KV 传输失败 / KV 字节异常 | **真错误** → 查 KV/精度，停止性能实验 |
| **D 无法判定** | a 或 b 不在两臂 top-20（算不出相对差距）；或 Δ_gap 不可估计 | 记录"无法判定"，**B2 不放行**；**不许**强行归入 B |

**稳健性重判（必做，措辞按此为准）**：用 **Δ_gap_max** 替代 Δ_gap_p95 把 B/C 重判一遍。

- 两线判定一致 ⇒ 按该判定走；
- **两线判定不一致 ⇒ 说明结论对阈值敏感，本轮不具备足够稳健性，B2 不放行**——
  这**不是**"真错误"，也**不等于** KV 损坏的指控，只是证据不稳。
- 不许挑对自己有利的一条用；阈值不许事后调整。

⚠️ **判据为什么用"竞争词相对差距"，不用"单 token 概率差"或"分布差 ≤ 同臂噪声"（别改回去）**：
① 每一边的 top2 不一定是同一个竞争 token，所以"min(两臂 top1−top2)"对一般情况不严谨，
判定一律用**实际翻转的那一对**（a=对照臂选择、b=拆分臂选择）；
② E2 实测跨臂分布差 0.01–0.03 远大于同臂重复噪声（中位 1e-5），按"分布差 ≤ 同臂噪声"
定义近并列会把 q04 误判成真不一致。正确问法是"翻词那步两个词本来差多少（q04 实测
0.011–0.026）是否小于 Δ_gap"。（依据：浮点非结合性研究的 tie-flip 概念，见 §10。）

**已知的诚实边界**：若 Δ_gap_p95 实测小于 q04 的 G，q04 判 C、B2 不放行——这是本口径接受的
可能结局（负结果也是结果），不许因此回来改判据。

  **落地方式（冻结）**：preset 加进 `b1_client.py` 的 `PROMPT_SETS`（新增 `cal10` 键，
  v1/v2 一字不动），不放别的脚本——生成器只有一个，避免两处规格漂移。
- **协议**：每条校准题取对照臂参考序列，在 k = 1, 3, 8, 15, 30（到 L 截止）五个位置回放，
  每位置**同臂重复 10 次**，得同臂重复的分布差 → **Δ_cal**（报中位 / p95 / max）。
- **硬件各测一次**：4060 的 Δ_cal 不能拿来判 A10 的数据。
- **作用**：① 自检同臂确定性（Δ_cal 预期≈0，PREREG_3 的 E3 曾逐位相同）；
  ② 若 Δ_cal > 0，它是真噪声地板；③ 合理性对照：若 **Δ_gap ≫ Δ_cal（超过一个数量级）**，
  如实报告"跨路径差远大于重复噪声"（这本身是重要发现，不改变判定——判定用 Δ_gap）。
- **不做的事**：不拿 0.05 或任何拍脑袋数字当线；不拿 Δ_cal 替代 Δ_gap 做判定。
- **附带自检**：校准回放同时完成 §2.1 的 top-20 非退化检查（顺手就有数据）。

## 6. 干预臂（因果检验；各约一次服务重启）

前提已核对：vLLM 0.31.0 文档含 batch invariance；Qwen2.5 系列在官方验证清单；
硬件门槛 CC≥8.0（A10=8.6、本机 4060=8.9）。

| 干预 | 做法 | 假设成立 ⇒ | 假设不成立 ⇒ |
|---|---|---|---|
| **I1 批不变性** | 两臂启动加 `VLLM_BATCH_INVARIANT=1`（`b1_remote_serve.sh` 的 `B1_BATCH_INVARIANT=1`），重跑 §3（5 诊断题） | 分歧消失/大幅减少 | 分歧照旧 |
| **I2 fp32** | 两臂加 `--dtype float32`（`B1_DTYPE=float32`；1.5B ≈ 6 GB 显存放得下），同上 | 分歧消失/大幅减少 | 分歧照旧 |

**I1 的"开关真的生效"验证（本机验收项 ★，不许只看环境变量存在）**：

1. 同一个提示词，**单请求**运行，记输出 token + processed 分；
2. 同一个提示词，放进**不同批大小**运行（如 1 / 3 / 8 个并发请求混排）；
3. 比较两种情况的输出 token 与 processed 分，记录**开关前后是否有变化**（批不变性打开时，
   不同批排布下同输入应给出相同结果）；
4. 开关关掉重做一遍作对照；
5. **若 vLLM 0.31.0 不支持或无法确认生效 ⇒ I1 记为"未执行/未验证"，不得作为因果证据**，
   报告里如实写"干预未验证"。

**I1 失败不阻止基线收口**（基线判定只依赖 §3/§4）。顺序：基线（bf16）→ I1 → I2；
每臂开测前过 C1 冒烟 + E3 自检。干预结果**只作归因诊断，不进性能实验**（开了会变慢）；
它不是"新增概率解释路线"——只是"数值路径敏感"这条已有假设的干预臂。

**C1 冒烟（每臂开测前，沿用 PREREG_3 §2）**：同一服务跑 `q01_rep6 / q02_rep10 / q03_rep14`
三条（不进统计），"吐词 == processed 第一名"全过才开测；不过**不采数**，回校准。

## 9. B2 放行闸门（冻结；六条全过才放行）

1. **KV 完整性证据全过**（4b 不变：接收端字节数、传输次数、无本地重算、失败计数 0）；

  **不写成"真错误"，不指控 KV**；
