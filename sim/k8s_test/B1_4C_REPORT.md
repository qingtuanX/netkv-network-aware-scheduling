### 5.2 但原始数字指向另一个故事 —— **这是一条事后观察，不是改判**

把 top-5 原文摊开看（同样取自 r2，原文照抄）：

```
[p01_rep8] 第 16 个 token
  对照臂: 实际选 ' use'   p=0.1966
      top5: ' execute'=0.5344  ' use'=0.1966  ' assign'=0.1966  ' allocate'=0.0235  ' send'=0.0183
  拆分臂: 实际选 ' assign'  p=0.2169
      top5: ' execute'=0.5202  ' assign'=0.2169  ' use'=0.1914  ' allocate'=0.0229  ' send'=0.0178

[p02_rep12] 第 20 个 token
  对照臂: 实际选 ' executing'  p=0.0531
      top5: '.'=0.5040  ' to'=0.2698  ' executing'=0.0531  ' handling'=0.0414  ','=0.0322
  拆分臂: 实际选 '.'  p=0.5329
      top5: '.'=0.5329  ' to'=0.2517  ' executing'=0.0496  ' handling'=0.0386  ','=0.0301

[p05_rep24] 第 55 个 token
  对照臂: 实际选 ' It'  p=0.4978
      top5: ' It'=0.4978  ' The'=0.2351  ' No'=0.0594  ' There'=0.0525  ' This'=0.0248
  拆分臂: 实际选 ' No'  p=0.0667
      top5: ' It'=0.4928  ' The'=0.2328  ' No'=0.0667  ' There'=0.0519  ' This'=0.0245
```

**三条观察**：

1. **两臂的整张概率分布几乎重合**：每一步对应候选词的概率差**最大不超过约 0.03**
   （p01 的 `' execute'` 0.5344 vs 0.5202；p05 的 `' It'` 0.4978 vs 0.4928）。
   也就是说，**两台机器对"下一个词该是什么"的看法基本一致**。
2. **翻转发生在几乎并列的候选词之间**：p01 上对照臂自己给出的
   `' use'=0.1966` 与 `' assign'=0.1966` **精确相等**（真正的并列），
   两臂只是把这种并列**断向了不同的一侧**。p02、p05 同理（竞争词之间只差几个千分点）。
3. **这与"KV 传坏了"完全不符**：传坏会让概率分布**整体走形**，
   不会只在小数点后第三四位上抖一下。§8 的 KV 证据也从另一侧排除了这一点。

### 5.3 对判据的检讨（**必须写出来，不能藏**）

**冻结的判据 `gap = top1 − top2` 量错了对象。** 它看的是"第一名领先第二名多少"，
但这次翻转发生在**第二名与第三名之间**（p01：`' use'` vs `' assign'`），
而第一名 `' execute'`（0.53）根本没被选中。
所以 `gap` 很大（0.34）**并不能**说明"这不是并列翻转"。

⇒ **正确的说法是**：

- **判定**：4c **不等价**（预注册 §6，照旧）。
- **对原因的解释**：按冻结规则为「确定性路径差异」；
  **但事后看，这条规则对本次的情形是失效的**，原始数字更支持
  「在两台机器各自都近乎并列的位置上，**极其微小的数值差异把 argmax 翻到了另一侧**」。
- **这属于新假设，不是结论。** 要验证它，必须**另行设计判据并预先写下**（见 §10），
  **不能拿这条事后观察把既有的"不等价"放宽成"通过"**（这正是 B1 被否掉的那个错）。

## C.1 现象
