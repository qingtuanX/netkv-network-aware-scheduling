# B1 4c 解决方案：从“逐 token 必须完全相同”转为可解释的正确性验证

> 记录日期：2026-10-09
> 本文件是新的技术方案，不修改 `B1_REPORT_2.md`、`B1_4C_REPORT.md`、
> `B1_4C3_REPORT.md` 或已有预注册。
> 现有结论保持不变：4c = 6/15，B1 整体未通过。

## 1. 已经确认的事实

1. 真实拆分服务能运行。
2. KV 缓存确实从前处理端传到了生成端。
3. 生成端没有自己重算输入，且传输失败计数为 0。
4. 单机完整服务和拆分服务在部分请求上输出不同。
5. 两条臂各自重复时可以稳定复现，所以差异不是简单的随机噪声。
6. `raw_logprobs` 不能用于解释选词；`processed_logprobs` 与温度、重复惩罚、截断规则处理后的选词一致。
7. 新诊断中出现了“竞争词概率接近”的现象，但这只能说明一种可能解释，不能证明差异来自 KV 传输。

## 2. 为什么原来的逐 token 判定过严

vLLM 官方的复现说明指出，在线服务的结果默认不保证完全复现；即使设置随机种子，
也要在相同硬件和相同版本下才有复现保证，在线服务还会受到批处理和调度影响。
官方另外提供了 batch invariance（让不同批处理顺序尽量不改变结果）的控制方式。

因此，前处理端和生成端虽然硬件型号相同，但它们不是同一条计算路径：

```text
单机臂：同一进程内完成前处理 + 生成
拆分臂：A 机器前处理 → KV 传输 → B 机器生成
```

在两个候选词几乎同分时，最后几位浮点数的微小差异可能改变最终选择。
这不能自动证明结果错误，但也不能自动证明结果正确。

## 3. 新方案：两层验证

### 第一层：严格控制执行环境

下一轮若要开云机器，必须先固定：

- `--generation-config vllm`，避免模型文件里的默认生成参数偷偷覆盖实验设置；
- 显式设置 `temperature=0`、`top_p=1`、`top_k=1`、`repetition_penalty=1`；
- 关闭前缀缓存、投机解码和不必要的多卡并行；
- 两端相同的 vLLM、NIXL、模型 revision、精度、注意力后端和 KV 布局；
- 若目标版本支持，启用 `VLLM_BATCH_INVARIANT=1`；先用 `vllm --help` 和版本源码确认，
  不把新版本环境变量直接套到 0.31.0；
- 单请求、串行、无背景流量，先验证基准自身重复，再比较拆分臂。

这些控制不是为了保证跨机器逐位相同，而是为了去掉可以主动消除的变量。

### 第二层：同一前缀的下一步分布比较

不能只比较完整生成后的文本。新的核心测试叫“固定前缀测试”：

1. 先由单机基准生成一条完整 token 序列。
2. 对每个已知前缀，分别把“原始 prompt + 该前缀”交给单机臂和拆分臂。
3. 两边每次只生成 1 个 token，并且使用 `processed_logprobs`。
4. 比较同一个前缀下两边的：
   - 下一 token 的最高候选是否一致；
   - top-k 候选集合重合程度；
   - 两边对同一候选 token 的概率差；
   - 两边完整 top-k 分布的最大差值。

这样两边在每一步看到的是同一个前缀，不会因为前一步已经选了不同词而越走越远。
它直接回答“KV 传过来后，下一步模型状态是否仍然一致”，比单纯比较最终文本更接近 4c 的本质。

## 4. 新的结果分类

这不是修改旧的 B1 放行标准；它是后续诊断和未来论文的补充证据。

### A. 高余量一致

如果单机基准的第一名与第二名差距明显，且拆分臂给出的 top-k 分布也一致，
则要求两边选出的 token 一致。这类位置可以作为“数值稳定位置”。

### B. 低余量分歧

如果两个候选词本来就非常接近，且两边的完整分布差异处在同臂重复测得的数值波动范围内，
则标记为“近并列、对执行路径敏感”。

这类位置不能写成“KV 错误”，也不能写成“完全等价”；只能说最终 token 选择对微小数值差敏感。

### C. 大余量分歧

如果单机第一名明显领先第二名，而拆分臂给出的分布却明显改变，或者生成端出现本地重算、
传输失败、KV 字节不对，则判为真实一致性问题，停止后续性能实验。

## 5. 阈值怎么定

不直接拍一个固定的 0.05。先用**独立校准题**测同一臂重复运行的自然波动：

- 用 10 条不进入正式诊断的合成题；
- 同一环境、同一请求连续运行 10 次；
- 计算同一前缀下 top-k 概率差的中位数、p95 和最大值；
- 预先把 p95 或最大值写成数值波动上界；
- 正式诊断题不得参与这个上界的计算。

正式比较时：

- 差异不超过校准上界：归入“数值波动相容”；
- 超过校准上界但 KV 仍完整：归入“执行路径差异”；
- 同时出现 KV 传输异常或生成端重算：归入“服务正确性失败”。

## 6. 执行顺序

### 第 0 步：不租云的本机校准

- 校验 `raw_logprobs` 与 `processed_logprobs` 口径；这一步已经完成；
- 修正分析脚本中把 logprob 差当普通概率差的问题；这一步已另存校正版；
- 在本机确认固定前缀测试的请求格式、token 对齐和产物格式；
- 不把本机单卡双实例结果当成跨机证据。

### 第 1 步：云端短时复核

- 重新启动两台 A10 前先确认新公网 IP、账单、预算和节省停机模式；
- 只跑控制项和固定前缀测试；
- 先跑 10 条校准题，再跑正式诊断题；
- 每次请求保留两端原始响应、处理后分、KV 指标前后快照和 manifest；
- 不跑吞吐、并发、费用收益或跨云对照。

### 第 2 步：决定是否进入 B2/C/D

- 如果高余量位置一致、低余量位置出现可解释分歧、KV 完整：可以把 4c 改写为“数值路径敏感，
  但未观察到 KV 损坏”，仍不宣称完全等价；是否进入 B2 需另行冻结正确性口径；
- 如果高余量位置也大量分歧：停止，继续查服务配置、算子或 KV 布局；
- 如果指标无法逐请求或固定前缀对账：停止，不进入性能实验。

## 7. 文献依据与定位

- vLLM 官方复现说明：默认不保证结果完全复现；在线服务只能用 batch invariance 等方式减少批处理影响，
  且复现保证限定在相同硬件和相同版本。该说明直接支持“不能把跨执行路径逐 token 相同当作默认事实”。
- vLLM 官方 batch invariance 示例：把批处理顺序变化作为影响输出的因素，并提供相应控制方式。
- vLLM 官方拆分式前处理说明：前处理和生成在不同 vLLM 实例中运行，功能仍属实验性；因此本项目应把
  KV 完整传输、输出正确性和性能收益分开验收。
- vLLM issue #9567：报告温度为 0 时，批处理大小不同也会改变输出，说明在线执行形状本身会影响结果。
- vLLM issue #58899：报告运行时算子调优造成温度为 0 的输出跨进程变化，说明微小浮点差异足以影响贪婪输出。
- DistServe（OSDI 2024）和 Mooncake（FAST 2025）主要用首字等待、逐字间隔、服务等级和有效吞吐评价拆分服务，
  不把逐 token 完全一致作为系统收益判据。它们支持本项目把“传输完整性”和“输出/分布一致性”分开报告。

- 4a：通过；

改成能区分 KV 损坏、数值近并列和真正路径差异的证据链。
