## 0. 结论口径（跑完后照抄；措辞已按 §8 边界写好）

> 在同云、同模型、同请求参数、同输出长度下，拆分部署相对单机部署的**整体开销**为：
> 首字等待 +X%、每请求平均 token 间隔 +Y%、总耗时 +Z%（四轮逐轮配对差见表，
> 一般差 …，波动范围 …）；**KV 传输量**（直接传输度量）W GB / N 次 / 失败 0；
> 失败率两边各 …。

## 3. 服务参数与请求参数（两臂**逐项一致**；与客户端实际发送逐项对齐）

**服务侧（两臂完全相同，无任何概率记录设置）**：
`--generation-config vllm --dtype bfloat16 --no-enable-prefix-caching`，
其余同 PREREG_4 布局（`--max-model-len 8192 --gpu-memory-utilization 0.85
--enforce-eager`；拆分两端 P=A:8100 D=B:8200 代理=A:8192，`start-decode` 末位
传 B 自己的内网 IP）。
⚠️ **删掉** 4c 用的 `--logprobs-mode processed_logprobs`——B2 不做概率分析，
两边服务配置必须一致（v1 草稿此处写错）。

**请求侧（= `b2_perf_client.py` 的 GEN_PARAMS + FIXED_PARAMS，改一处必须改两处）**：

| 参数 | 值 | 用途 |
|---|---|---|
| temperature / top_p / top_k / repetition_penalty / seed | 0 / 1 / -1 / 1.0 / 0 | 生成钉死 |
| **max_tokens** | 64 | 固定输出长度（配合 ignore_eos） |
| **ignore_eos** | **true** | **每条真生成 64 个 token**，工作量相同才可比 |
| **logprobs** | **0** | **只为在流式块里读 token ID，不取概率值** |
| stream | true | 流式计时 |

**实际生效证据**（照 PREREG_4 纪律）：启动日志 non-default args、实发 payload
（产物里 `request_params_actual`）、逐请求 token 数=64 核对（本机已验：64/64）。
三端脚本 sha256 一致检查（check+sync 照旧）。

## 4. 指标（命名与 vLLM 文档对齐："块"≠"token"）

| 指标 | 来源 | 读法 |
|---|---|---|
| **TTFT（首字等待）** | 第一个输出块到达时刻 | 拆分的 KV 传输开销主要砸在这里 |
| **文字块间隔**（chunk gap） | 相邻输出块到达时刻差 | ⚠️ 一个块可能含多个 token，**不叫"逐字间隔"**（v1 命名错误） |
| **每请求平均 token 间隔** | (末块−首块)/(token 数−1)，token 数由块内 **token ID** 数出 | 生成阶段速度；**交叉核对**：两臂都取 /metrics 的 `vllm:request_time_per_output_token_seconds`（服务端**按请求观测后汇总的间隔分布**，用于和客户端整体结果交叉核对；**不用于逐请求配对**——汇总桶不带请求编号）与 `vllm:request_generation_tokens` |
| **总耗时** | 64 词收完 | 固定工作量下可比 |
| **失败率** | 错误/超时 ÷ 总数 | 失败保留，不重试（§6） |
| **KV 传输量** | **两臂都取** /metrics t0→t1（nixl 字节/次数/失败；`vllm:request_prefill_time_seconds` 同采） | base 臂应为 0（对照）；这是"传输"的直接度量 |
| **费用** | 实例小时 × 控制台单价 | 记录开机/停机时刻与费率来源 |
| **长度核对** | 每请求 token 数（token ID 数出） | 应全部=64；不等按 §6 预写规则处理 |

产物（append-only）：`sim/results/b2/<run_id>/`
`perf_<arm>_s<轮>_c<并发>.json`（工具原生格式，含 token ID 数与 `request_params_actual`）、
`metrics_<arm>_s<轮>_t{0,1}.txt`、`record.csv`（每轮：形态顺序/档顺序/题序种子/
预热/冒烟/重启耗时/异常）、`decision.json`（§7 逐条 + §0 结论）。

## 5. 统计口径（防伪重复 + 防过度宣称）

- **独立重复的单位是"配对轮"（n=4）**。形态是服务级干预，一轮里的大量请求只是抽样，
  **不冒充独立试验**（伪重复）。
- **配对**：同一 (题, 重复号, 并发档) 的 base vs disagg 成对；每轮内聚合成轮级配对差。
- **报告方式（不写"95% 置信区间"）**：
  ① **逐轮配对差表**（4 行，每轮一行）；
  ② **一般差多少**（四轮配对差的中位数）；
  ③ **波动范围**（四轮的 min–max）。
  四轮太少，自助法区间不是可靠的置信区间，**不作推断宣称**。
- 每请求的 p50/p95（含慢尾）**只作描述**，标注"描述性，非推断"。

## 6. 顺序平衡（随机化 + 区组，不是"重复但全固定"）

每轮 r∈{1..4} 内：

| 顺序 | 规则 | 防什么 |
|---|---|---|
| **形态顺序** | ABBA：轮 1、4 base→disagg；轮 2、3 disagg→base | 时间漂移错算进形态差异 |
| **并发档顺序** | 轮 1、3 串行先；轮 2、4 并发先（逐轮全表见 `B2_RUNBOOK.md` §1） | 档序与时间纠缠 |
| **题序** | 每轮用**记录在案的种子**置换 5 题；**同一轮内两形态用同一题序** | 固定题序的顺序效应；两臂同序才配对得干净 |

- **单请求失败不重试**：失败就是"失败率"这个指标的一部分（与正确性采数的重试规则
  刻意不同，理由在此）。
- 整轮基础设施中断（ssh 断/机器重启）⇒ 该轮标 `infra_abort` **整轮重跑**，原始产物保留。
- **token ID 严格规则（v2.1，作者裁定）**：token 数只认块内 token ID（`logprobs.tokens`），
  **不得用块数冒充**。正式采数中出现任意一次收不到 token ID ⇒ 该请求记
  `token_count_invalid`、**该格作废**、工具退出码 2 立即停该格，先检查、不补采同格。
  汇总计数 `n_token_source_fallback` / `n_token_source_invalid` 在正式采数中必须全为 0。
- **长度不等配对的预写规则**（固定长度模式下应不触发，触发了照此办）：
  ① 实际 token 数≠64 的请求记 `length_ok=false` + 实际长度 + finish_reason；
  ② 总耗时配对比较**只纳入两侧长度相等的对**；
  ③ 长度不等的对改报"每 token 平均耗时"（总耗时÷实际 token 数），单独列表；
  ④ 一个格子内长度不等的对 > 10% ⇒ **该格作废**（§7 检查 7）。
- **砍臂优先级**（预算/时间不够按此砍，manifest 记录）：
  ① 会话 4→2 轮（AB/BA 仍反平衡）② 重复 10→5 ③ 并发档砍并发 4。

## 7. 有效性检查（decision.json 逐条勾选）

1. 参数实际生效（启动日志 + 实发 payload + 非退化）；
2. 预热轮执行且未混入统计；
3. C1 冒烟每形态每轮全过；
4. 每格有效请求 ≥ 30；
5. **长度核对**：正式请求全部 64 token（或按 §6 规则处理且不等对 ≤ 10%）；
6. **token ID 来源**：所有正式请求 `token_count_source=logprobs_tokens`
   （`n_token_source_fallback=0`、`n_token_source_invalid=0`）；
   出现 `chunk_fallback` 时**该格作废，不得用块数代替 token 数**；
7. ABBA + 档序 + 题序种子执行与记录（record.csv 与时间戳一致）；
8. KV 账目自洽（拆分臂字节/token ≈ 28,796，与 4c 同一核对；base 臂=0）。

**全过 ⇒ B2 数据可作 C/D 的对照锚点**；不过 ⇒ 对应格子作废，照实记。

## 8. 解释边界（写论文时照抄，不得越界）

- **base 臂用 1 张 GPU（B 机完整服务），disagg 臂用 2 张 GPU（A 前处理 + B 生成）**。
  因此测到的是**两种部署方式的整体差异**（含算力配置不同、流水线并行、KV 传输、
  代理跳数），**不得**把端到端时间差称为"传输成本"。
- **KV 传输字节数/次数/失败**单独报——这才是"传输"的直接度量。
- 延迟与费用一律称"**部署方式整体开销**"。
- **token 计时的解释边界（冻结时明确）**：若一个输出块含多个 token，
  `chunk_gap_s` 只是"文字块间隔"；`avg_token_gap_s` 只能解释为
  **"整段输出时间跨度除以 token 数"**，不能声称拿到了每个 token 的真实到达间隔；
  服务端 `vllm:request_time_per_output_token_seconds` 只作整体交叉核对，不做逐请求配对。
- ignore_eos 固定 64 词保证工作量可比，代价是"自然停止"场景未覆盖——如实声明。
