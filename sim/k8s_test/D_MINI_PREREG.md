## 0. 唯一的问题与停止规则（作者裁定原文）

**停止规则**：若小规模验证仍显示跨云明显变慢 ⇒ **停止 D，C 作为正式负结果收口，

## 1. 设计（极简；不加矩阵）

| 因子 | 冻结值 |
|---|---|
| 模型 | Qwen2.5-1.5B（**不换**）；服务参数与 C 完全一致（UCX→wg0、WireGuard） |
| 输入长度 | **2 个新长度**：目标约 1024 与约 4096 token（确定性合成文本；用冻结分词器记录实际输入 token 数，实测 KV 字节作为主横轴） |

## 2. 判据（冻结）

1. 对每个长度先取 3 次的中位数，再计算**首字等待 ~ 实际 KV 字节**的两点斜率（秒/GB）。
   主结果同时报告 D1、D2 的跨云斜率，以及跨云减去同云参考臂后的增量斜率。
2. 同云参考臂只作为部署参考，不能声称完全剥离 D2 的腾讯 GPU/驱动差异；D2 的增量斜率仍须
   标注为“部分控制后的描述性结果”。
3. 以 C 阶段实测跨云数据通道带宽作预先冻结的搬运参考：D1 使用 A→T **8.6 MB/s**，
   D2 使用 T→B **11.7 MB/s**；比较实测增量斜率与 `1 / 带宽` 的量级。
4. **±25% 线**只用于工程上的相容性检查：增量斜率落在 `1 / 带宽` 的 `[0.75, 1.25]`
   倍范围内，记为“在本次两个新增长度范围内与线性搬运模型相容”；超出则记为“本次范围内
   不相容”。两点不能证明所有输入长度都普遍线性。
5. C 阶段 q01–q05 的事后分组只作背景图和探索性参照，不能用于反向调整本轮判定线。
   结论措辞限于“本次两个新增长度范围内是否与线性模型相容”；不作跨云收益结论。
