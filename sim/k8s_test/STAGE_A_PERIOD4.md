## 6. ⚠️ 脚本的"作废即重跑"逻辑与附录 B.2 的冲突（单列一节，不含糊）

### 6.1 冲突是什么

**附录 B.2 要求**：① 每一次**已经开始的**正式测量都必须留档；
② **字节不一致 / 限速计数未增加 / 丢包超限 → 一律记为失败，停下排查，不得静默重跑来替换**；
③ **只有"测量前的限速安装检查未通过"**才算"未开测"（仍保留记录，但不计作正式测量轮）。

**批次脚本 `run_stage_a_repeat.sh` 的实际行为**：对每一轮做 `MAX_ATTEMPTS = 4` 次尝试，
触发以下任一条件就**作废该次尝试并重跑**（原始产物保留 + 写 `_VOID.txt` + 追加 `batch_*_voided.csv`）：

| 脚本的作废条件 | 属于 B.2 的哪一类 | 与 B.2 是否一致 |
|---|---|---|
| 限速在位断言失败（重设后仍失败） | **测量前**（未开测） | **一致**（B.2 第 3 条） |
| `tc` 统计读不到 `overlimits`（`-s` 缺失/仪表挂） | **测量前** | **一致** |
| 功能探测不涨（`overlimits` 未增加） | **测量前** | **一致** |
| `A1` 字节一致 FAIL / `A1` 有 N 项 FAIL | **已开测之后** | **冲突**（B.2 第 2 条：应记为失败并停下排查） |
| 工具 `A2` 无有效读数（请求失败） | 已开测之后 | **冲突**（同上） |
| 工具 `A3` `overlimits` 增量 = 0 | 已开测之后 | **冲突** |
| 本轮整轮 `overlimits` 增量 ≤ 0 | 已开测之后 | **冲突** |
| `iperf3` 无有效读数 | 已开测之后 | **冲突** |
| 轮内轮询没看到 `htb` / 看到 `mq` | 已开测之后 | **冲突** |
| 并发段 3 路合计 > 1.8× 设定值 | 已开测之后 | **冲突** |

**任务要求"脚本一字不改"（只传参），所以本次照原样跑。**

### 6.2 本次（以及全部 4 个时段）实际发生了什么

| 项 | 实测 | 证据 |
|---|---|---|
| 正式测量轮数 | **50 轮**（pilot 40 + 本段 10） | 四个 `batch_*_rounds.csv` |
| **作废次数** | **0 次** | 四个 `batch_*_voided.csv` **都只有表头**；四个目录 **0 个 `*_VOID.txt`** |
| 日志里的"作废（原因…）" | **0 条** | 四份批次日志 |
| 测量前的重试 | **0 次**（无"断言失败"、无"功能探测失败"） | 四份批次日志 |
| 每轮的尝试序号 | **50/50 全部是 `attempt = 1`** | `rounds.csv` 第 5 列 |
| 被丢弃或替换的轮次 | **0 轮** | 归档的轮次集合 == 实测的轮次集合 |

**结论（照实写）**：**这次冲突没有实际发生**——脚本的作废逻辑在 4 个时段、50 轮里**一次都没触发**，
所以**没有任何一轮被"重跑替换"**，B.2 的"不得静默重跑替换"没有被违反（也没有机会被违反）。
**但冲突是真实存在的设计层面的不一致**：脚本内置了"已开测之后也能作废重跑"的能力，
这与 B.2 第 2 条相抵触；**如果**将来某一轮触发了上表后半部分的任一条件，
脚本会静默重跑，而 B.2 要求在那一轮**记为失败并停下排查**。

### 6.3 若将来真的触发，报告应当怎么写（本次未触发，但先把规矩写清楚）

1. 作废的那次尝试**必须当作正式测量轮呈现为【失败】**：它的全部产物（6 份 `tc` 原文、轮询、
   工具 stdout/CSV/JSON、`iperf3` JSON、探测日志）脚本都**已经保留**，另有 `_VOID.txt` 与
   `voided.csv` 行标注原因；
2. **不得**只用重跑成功的那条替换它；报告里该轮应出现**两行**（失败尝试 + 重跑），
   且失败的那次**计入分母**（这正是 B.2 第 2 条的算法效果）；
3. 本文件所报的"作废 0 / 50 轮全部首次尝试"，就是按这个口径核对出来的（§6.2 的表）。

> **一句话**：冲突**存在**、**本次未触发**、**没有数据被丢弃或替换**；
> 但"脚本具备静默重跑的能力"这件事**必须写进正文的方法学说明**，
> 否则读者会以为"有效轮 100%"是脚本替我们筛出来的。
