# arXiv 每日简报（大模型 / AI Infra）

**一句话**：每天早上自动抓 arXiv 当天新论文，先用关键词粗排、再让大模型挑出「和你研究方向有关的」
和「AI Infra 求职向的」，翻成中文、写成摘要，先推一条微信（手机上直接看），再推一条 PDF 直链清单。

已经装好并跑通：Windows 计划任务每天 08:10 / 09:10 抓取（免费），08:15 在界面里播报；
微信推送走本机 `~/.dsh/wxbridge` 通道。

---

## 一、它每天产出什么

```
tools/arxiv_daily/
├── arxiv_daily.py          主程序（标准库 + 一次大模型调用）
├── config.json             全部可调参数（分类、关键词、轨道、翻译、推送）
├── install_task.ps1        装/卸 Windows 计划任务
├── briefs/2026-10-22.md    完整中文日报（人看）+ 同名 .json（机器用）
├── state/seen.json         去重台账
└── logs/run.log            每次运行的日志
```

**微信会收到两条消息**（按你说的「先摘要、再文件」的顺序）：

第一条是正文，长这样（实测 2805 字）：

```
arXiv 日报 2026-10-22（周四）
本期新增 184 篇，筛出 8 篇推荐：
窗口 10-20 18:16 → 10-22 00:16（北京时间）

【一、你的方向 · 推理服务与调度】4 篇

1. 超越点质量：投机解码中基于接受度的权重与分布损失
   原名：Beyond the Point Mass: Acceptance-Derived Weights and Distributional L…
   讲什么：针对投机解码中 D-PACE 将目标分布视为点质量的问题，作者从拒绝采样下接受概率
           等于草稿与目标分布重叠出发，推导出 D-PAL 损失，用重叠度作权重、对数接受率作
           逐位置损失，以更准确地优化期望接受长度。
   为什么推你：投机解码加速推理，与推理服务吞吐直接相关
   摘要页 https://arxiv.org/abs/2610.28355 ｜ PDF https://arxiv.org/pdf/2610.28355
...
【二、AI Infra · 引擎 / GPU / 部署】4 篇
...
```

第二条是 PDF 直链清单（实测 457 字），手机上一条条点开就能看或转发：

```
PDF 直链（点开即可下载/转发）
超越点质量：投机解码中基于接受度的权重与分布损失 https://arxiv.org/pdf/2610.28355
LLM 解码的 Token-能量定律：… https://arxiv.org/pdf/2610.28576
...
```

**注意：微信里发不了 PDF 文件本体**，原因见第六节。现在给的是 arXiv 官方 PDF 直链，
点开就是原文，效果上接近「收到文件」。

日报文件（电脑上看）比微信更全：每条有作者、分类、交叉列表、中文摘要、命中关键词，
末尾还有「其他没进推荐的论文」标题清单。

## 二、每天自动跑

| 时间（北京） | 谁 | 干什么 | 花钱吗 |
|---|---|---|---|
| 08:10 | Windows 计划任务 | 抓 arXiv → 粗排 → 大模型分类翻译 → 写日报 → 推微信 | 大模型几分钱，本地部分免费 |
| 08:15 | 界面里的会话定时任务 | 读当天日报，在对话里回 8 行 | 少量 token（低谷价） |
| 09:10 | Windows 计划任务 | 冬令时兜底再抓一次（没新增就什么都不做） | 0 元 |

时间不是随便定的，三个约束叠在一起：

1. arXiv 只在美东时间周日到周四晚 20:00 公告；
2. 夏令时 20:00 = 北京次日 08:00，冬令时 = 09:00，所以固定一个点必然有一半时间抓空；
3. 大模型接口的低谷价时段大约到早上 08:30，再往后是高峰价。

于是：08:10 抓（夏令时刚公告完 + 还在低谷），09:10 兜底（冬令时），08:15 让界面那条也在低谷窗口里播报。

**冬天注意**：11 月到次年 3 月公告推迟到 09:00，08:15 时当天那批还没出，
界面里那条只回一句「今天这批 09:00 才公告，微信稍后会到」。微信那条由 09:10 的任务发，不受影响。

常用命令：

```powershell
Get-ScheduledTask -TaskName arXivDailyDigest | Get-ScheduledTaskInfo
powershell -ExecutionPolicy Bypass -File tools\arxiv_daily\install_task.ps1 -RunNow
```

## 三、手动用

```powershell
sim\.venv\Scripts\python.exe tools\arxiv_daily\arxiv_daily.py               # 正常跑一次
sim\.venv\Scripts\python.exe tools\arxiv_daily\arxiv_daily.py --no-state    # 看全量
sim\.venv\Scripts\python.exe tools\arxiv_daily\arxiv_daily.py --dry-run     # 只抓不花钱
sim\.venv\Scripts\python.exe tools\arxiv_daily\arxiv_daily.py --no-push     # 只出文件不推微信
```

| 参数 | 作用 |
|---|---|
| `--window-hours N` | 往前看多少小时（默认 30） |
| `--max-results N` | 最多抓多少条（默认 1200） |
| `--out-dir DIR` | 输出到别的目录（调试用） |
| `--no-state` | 不去重、不写台账 |
| `--force` | 没有新增也生成 |
| `--dry-run` | 只抓取统计，不落盘、不调大模型 |
| `--no-push` | 不推微信 |
| `--open` | 生成后打开 |

## 四、想调就改 `config.json`

| 你想干什么 | 改哪个键 |
|---|---|
| 每条轨道推几篇 | `tracks.research.max` / `tracks.infra.max`（现在各 4） |
| 多抓/少抓方向 | `categories`（现在是 cs.CL / cs.LG / cs.AI） |
| 大模型多处理几篇 | `translate.max_papers`（现在 20；这是花钱的上限） |
| 关掉翻译和分类 | `translate.enabled = false`（退回英文标题 + 关键词分类） |
| 换个模型/接口 | `translate.base_url` / `translate.model` |
| 什么算「我的方向」 | `research_keywords` |
| 什么算「AI Infra」 | `infra_keywords` |
| 关掉微信推送 | `push.enabled = false` |

改完立刻看效果：`--no-state --out-dir tmp\check`（写到临时目录，不污染正式日报）。

## 五、大模型这块到底怎么工作（也说说钱）

一次运行大概是这样的：

1. 抓 400–700 篇（看当天公告量）；
2. 关键词粗排，取最像的 **20 篇**（`translate.max_papers`）——**不是 600 篇全给模型**，这是控成本的关键；
3. 一次请求让模型对 20 篇做四件事：判断属于「你的方向 / AI Infra / 其他」、翻中文标题、
   写 80–140 字中文摘要、写一句推荐理由；
4. 两条轨道各取 4 篇写进日报和微信。

**key 从哪来**：先读环境变量 `DEEPSEEK_API_KEY`；没有就从本机 DSH 凭据文件
`~/.dsh/.credentials.yaml` 的 `refs` 里取（脚本不打印 key）。想换 key 就设环境变量。

**花多少钱**：一次大约 1.5 万输入 token + 3 千输出 token，按 DeepSeek 的价格是**几分钱到一毛钱**；
08:10 那次在低谷时段还能再打折。`--dry-run` 完全不调模型。

**质量边界**：模型只看到标题和摘要（900 字符），**没有读正文**，所以摘要只代表「论文自己怎么说的」，
不代表它做得好。模型被要求「摘要里没有的数字不要编」，但小概率仍会措辞过度，重要论文请点原文核对。

## 六、微信推送：为什么是链接不是文件

**发不了 PDF 文件本体**，这是通道限制，不是我偷懒：本机这个微信桥
（`@zmainer/dsh-wx-bridge`）的 README 明确写着「只支持文本推送，插件目前没有出站附件通道」；
它只实现了 iLink 的两条接口：收消息和发文字，没有上传文件的接口。
给桥加「发文件」需要自己摸 iLink 的上传协议，风险是把现在能用的推送弄坏，我不建议动。

现在给的替代方案（已经在用）：

1. **PDF 直链**：`https://arxiv.org/pdf/2610.xxxxx`，手机点开就是 PDF，能直接保存、转发、收藏；
2. **摘要页直链**：`https://arxiv.org/abs/2610.xxxxx`，页面里有摘要和 PDF 按钮。

如果你确实需要「微信里收到文件」，还有两条路，都能做但要你先拍板：

- **邮件**：给我一个邮箱和 SMTP 授权码，我每天把 8 篇 PDF 打包发邮件（最稳，不依赖微信桥）；
- **局域网链接**：手机和电脑连同一个 Wi-Fi 时，我在电脑上开个静态文件服务，微信里发 `http://192.168.x.x:端口/日期.pdf`。
  缺点：手机用流量就打不开。

推送细节：消息写进 `~/.dsh/wxbridge/outbox/`，桥每 5 秒取件发送；「已入队」不等于「已送达」，
真送达看 `bridge.log` 里的 `push-sent`。两条消息之间脚本会睡 2 秒，避免顺序颠倒。
单条微信上限 4000 字，超了脚本会截断并提示。

## 六点五、期刊 / 会议（新增来源）

除了 arXiv，还会按「会场」去 Semantic Scholar 拉最近发表，覆盖期刊和会议。

覆盖方式：

- 每个会场一次请求，`query=*` + `venue=<会场名>` + `year=2025-2026`；
- 有 arXiv 版本的自动跳过（arXiv 那条已经报过，避免同一篇报两次）；
- 期刊论文没有 PDF 直链时，给 DOI 详情页链接；
- 同样进两条轨道、同样打推荐指数。

配置在 `config.json` 的 `venues`：

```json
"venues": {
  "enabled": true,
  "names": ["EuroSys", "MLSys"],
  "years": "2025-2026",
  "max_per_venue": 20,
  "request_gap_s": 8.0
}
```

注意事项（都是实测）：

- Semantic Scholar 免 key，但限流很紧，`request_gap_s` 是会场之间的强制间隔，429 会退避重试；
- 会场名要能被它认出来，认不出来就换全称（例如 `Symposium on Networked Systems Design and Implementation`）；
- **IEEE / ACM 的期刊常常没有摘要**，只有标题；这种只能翻标题，摘要为空；
- 期刊是滚动出版，会议是成批出，所以大多数日子「期刊会议新增 0 篇」是正常的。

## 七、踩坑与调优全过程（都是实际遇到的）

### 坑 1：写文件工具在 E: 盘直接报错

`EISDIR: illegal operation on a directory`。E: 是 **exFAT** 移动固态盘，写文件工具靠硬链接做原子替换，
exFAT 不支持。处理：先写到 C: 临时目录再复制。

### 坑 2：arXiv 查询不加括号，日期条件失效

加括号 239 条，不加 123453 条。必须写成 `(cat:A OR cat:B) AND submittedDate:[...]`。

### 坑 3：`submittedDate` 实际按公告日算

公告没出来前查当天是 0 条。所以定时任务必须放在公告之后，不能按自然日写死。

### 坑 4：周末没有公告，空日报是正常的

周日到周四晚公告，周五周六不公告。空的那天写一页「本期无新增 + 为什么」，不报错。

### 坑 5：冬夏令时差一小时

美东 20:00 = 北京 08:00（夏令时）或 09:00（冬令时）。所以两个触发时间。

### 坑 6：Windows 的 Python 没有时区库

`zoneinfo` 会抛 `ZoneInfoNotFoundError`。用固定 `+08:00` 偏移（中国不用夏令时）。

### 坑 7：中文 Windows 的 JSON 常带 BOM

`encoding="utf-8"` 读会抛 `Unexpected UTF-8 BOM`，一律用 `utf-8-sig`。

### 坑 8：控制台 GBK、pythonw 没有 stdout

启动时重置 stdout 编码；日志函数判空后再打印，文件一律 UTF-8。

### 坑 9：计划任务的工作目录不是脚本目录

全部路径用 `Path(__file__).resolve().parent` 推出来。

### 坑 10：关键词「network」几乎全是假阳性

"neural network" 也算 network。删掉 network/cluster/placement，换词组
（network bandwidth、gpu cluster、interconnect），第一节从 24 篇降到 12–13 篇。
现在最终分类交给大模型，关键词只用于「挑 20 个候选」，所以这个问题影响变小了，但仍然要避免。

### 坑 11：去重台账必须记「全部抓到的」，不是只记「列出来的」

否则被截断的那些明天会被当成新增再报一次。

### 坑 12：同一天跑两次会互相覆盖

有新增时先把已有 JSON 并回来；没有新增且当天文件已存在时什么都不动。

### 坑 13：arXiv 限流

两次请求间隔 ≥3 秒；User-Agent 带联系方式；403/429/5xx 指数退避重试。

### 坑 14：摘要里的 LaTeX 会把 Markdown 弄乱

`\emph{...}`、`$O(n^2)$`、标题里的换行都要清掉；XML 实体不要再 unescape 一次。

### 坑 15：第一次运行要先建基线

没有台账时会把整个窗口都当新增，所以在日报里写明「这是基线」。

### 坑 16：子进程输出用系统默认编码解码，中文变乱码

第一次接通推送时日志里出现 `宸叉帓闃燂細` 这种鬼画符：Python 用 GBK 解了 node 的 UTF-8 输出。
处理：`subprocess.run(..., encoding="utf-8", errors="replace")`。

### 坑 17：微信「推送成功」只是入队成功

`wxpush.mjs` 只把 JSON 丢进 outbox，桥每 5 秒取件。判断送达看 `bridge.log` 的 `push-sent`。
`node` 在计划任务里不一定在 PATH 上，所以 config 里写的是绝对路径。

### 坑 18：计划任务里起子进程要加 CREATE_NO_WINDOW

否则每次弹一个黑框。`creationflags=0x08000000`。

### 坑 19：微信单条 4000 字，超了会被截断

8 篇 × 每条 5 行 ≈ 2800 字，刚好。如果以后加到 12 篇就会超，脚本会自动截断并提示，
更好的做法是拆两条（现在正文和 PDF 清单本来就是两条）。

### 坑 20：一上来就把 600 篇丢给大模型，钱会烧得很难看

现在是「关键词粗排 → 只给 20 篇」。600 篇全给模型大约要 30 万 token，是现在方案的 20 倍。

### 坑 21：翻译会让模型「顺手编数字」

第一版提示词没约束，摘要里出现了原文没有的具体数值。现在提示词明确写「摘要里没有的数字不要编，
不要评价好坏」，并且 `--dry-run` 可以完全不调模型地检查抓取是否正常。

### 坑 22：微信推送会被「会话窗口」卡住，报 errcode=-2

现象：wxpush 排队成功，但 bridge.log 里是 `push-failed ... errcode=-2 prepare failed`。

连纯中文短句也发不出去，排除了内容和长度问题。

原因：iLink 主动推送依赖你最近一次给机器人发消息时留下的 context token。

你太久没说话，窗口过期，推送就被拒。

处理：在微信里给机器人随便发一句话（「你好」就行），token 立刻刷新，再推就通。

实测：你发完「你好」之后，三条消息全部送达（39 / 3048 / 470 字）。

延伸：这也是为什么推送失败不能只看「已排队」，必须看 bridge.log 的 push-sent。

### 调优记录

| 调整 | 之前 | 之后 | 原因 |
|---|---|---|---|
| 通知内容 | 3 篇标题 + 本地路径 | 8 篇中文摘要 + 直链 | 手机上路径没用，英文标题看不懂 |
| 分类方式 | 纯关键词 | 关键词粗排 + 大模型分类 | 关键词分不清「调度」和「neural network」 |

| 时间窗 | 26 小时 | 30 小时 | 手动补跑会切到半批 |
| 触发次数 | 1 次 | 2 次（08:10 / 09:10） | 冬夏令时 |
| 会话播报 | 工作日 09:20 | 每天 08:15 | 每天都要 + 避开 token 高峰 |

## 八、诚实边界

- **翻译和摘要是模型写的，只基于标题+摘要**，没读正文；重要论文必须点原文核对。
- **分类是模型判断 + 关键词兜底**，会漏也会错判；漏掉的你可以用 `--no-state` 看全量。
- **微信发不了 PDF 文件**，只能发链接（原因见第六节）；要文件得走邮件或局域网方案。
- **微信「已入队」≠「已送达」**，送达看 bridge.log 的 push-sent；桥挂了消息会排队，不会丢。
- 每天 400–700 篇里只推 8 篇，**没推的不代表不好**。
- 冬天（11 月—次年 3 月）08:15 那条播报会说「还没出」，这是时区决定的，不是 bug。
- 本工具在 `tools/` 下，和 `sim/` 的实验数据无关，不影响论文任何数字。
